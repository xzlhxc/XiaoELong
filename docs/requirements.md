# XiaoELong 需求文档

> 版本：2.1.0 | 日期：2026-08-12 | 基于用户访谈整理，随重构持续更新

---

## 一、产品定义

### 1.1 产品定位

XiaoELong（小鳄龙之家）是一个面向 **固定小群（~7 人）** 的 Windows/macOS 桌面伴侣应用。以悬浮桌宠为入口，集成轻社交功能，营造小群体专属的"每日互动仪式感"。

### 1.2 用户画像

| 维度 | 描述 |
|------|------|
| 用户数 | 固定 7 人，不对外扩展 |
| 平台 | Windows + macOS（无移动端） |
| 技术能力 | 混合，部分非技术用户 |
| 使用频率 | 每日多次（聊天）+ 每日一次（心情/答题/膜拜） |
| 关系 | 熟人小群，基于信任 |

### 1.3 产品属性

- **半严肃项目**：长期维护但不过度工程化
- **自用为主**：不开源推广，不追求用户规模
- **体验优先**：稳定、有趣、有仪式感 > 功能堆砌

## 二、功能需求

### 2.1 当前功能（V2.1.0，已实现）✅

#### F1 — 用户系统
- 邀请码入群（单邀请码，不含邀请人追踪）
- JWT 身份认证（REST Bearer + Socket 握手双重认证）
- 会话持久化（localStorage + Electron session.json）
- 个人资料编辑（昵称、头像）
- 账户注销

#### F2 — 实时聊天
- 文字消息（Markdown 可选，sanitize-html 防 XSS）
- 图片消息（jpg/png/webp/gif，单独上传 + 内联展示）
- 文件附件（任意类型，显示文件名和大小）
- 引用消息（右键引用，支持引用预览、历史记录与跳转原消息）
- 历史消息加载（默认最近 50 条）
- Socket.io 实时推送
- 独立图片查看器窗口

#### F3 — 每日心情
- 每天限选一次，16 种 Emoji 可选
- 全群实时同步（Socket 广播 `mood:update`）
- 心情翼装饰（EnergyWing 组件动画）

#### F4 — 每日一题
- 每天一道大学生向四选一题
- DeepSeek AI 生成 + 本地 Fallback 题库
- 结构化附图支持（`visual_type`/`visual_data`）
- 每人每题仅一次答题机会
- 全群实时统计更新
- 定时生成（node-cron，每天 8:00）

#### F5 — 神选膜拜
- 七位群友被封为"神"，每日可选一位膜拜
- 神阶系统：凡人→半神→真神→主神→创世神
- 星座主题视觉效果
- 全屏膜拜模式（DivineWindow）

#### F6 — 五子棋
- 邀请/接受/拒绝制对局
- 实时棋盘同步（Socket 推送）
- 服务端胜负判定（四方向扫描）
- 数据库事务 + 行锁保证并发安全

#### F7 — 桌面壳
- 悬浮桌宠窗口（透明无框、可拖拽、始终置顶）
- 功能面板窗口（紧邻桌宠自动定位）
- 精灵动画系统（PetSprite + pet-animation 状态机）
- 系统托盘（显示/隐藏/退出）
- 开机自启（可配置）
- 窗口置顶开关
- 桌宠显示模式切换（仅形象/仅面板/两者）
- Windows 自动更新（electron-updater）
- macOS 手动 DMG 更新（GitHub Release + latest-mac.json）

### 2.2 未来规划功能（优先级排序）

> 以下功能已有想法，但不急于实现。当前阶段先重构代码架构成可扩展状态，再逐步添加。

#### 规划 — P1（架构就绪后优先考虑）

##### F8 — 聊天增强
- **消息撤回**：发送者可在限定时间内撤回消息，服务端软删除
- **@提及**：在消息中使用 `@用户名` 提及特定用户，被提及者收到高亮通知
- **未读计数**：标记自上次查看后的新消息数量

##### F9 — 管理功能
- **管理员角色**：指定群管理员，有权撤回任意消息
- **邀请码管理**：管理员可重新生成/查看邀请码
- **群设置**：群名称、群规等配置

#### 规划 — P2（中期扩展）

##### F10 — 更多游戏
- **画猜接龙**：画图+猜词每个人接龙，异步进行，不计时，方便摸鱼
- **成语接龙**：文字游戏，可结合 AI 判题
- 游戏体系应抽象为"游戏框架"，统一管理游戏状态

##### F11 — 表情包系统
- **自定义表情**：群成员上传 GIF/图片作为表情
- **常用表情栏**：按使用频率排序
- 需注意存储空间管理

##### F12 — 日历/日程
- **群日历**：标记群成员生日、纪念日等
- **每日提醒**：结合桌宠弹出提醒气泡
- 与每日心情/每日一题形成"每日仪式"闭环

##### F13 — 更丰富的桌宠行为
- **AI 对话**：接入 LLM，桌宠可进行简单对话（类似桌面助手）
- **情境感知**：根据时间/聊天内容/心情做出不同动画反应
- **互动道具**：群成员可使用"道具"触发桌宠特殊反应

#### 规划 — P3（远期畅想）

##### F14 — 数据统计与回顾
- **年度回顾**：聊天热词、常用心情、答题正确率等
- **群成就系统**：连续答题天数、游戏胜率等
- 纯趣味性，不制造排名压力

##### F15 — 语音消息
- **对讲机模式**：按住说话，发送短语音
- 文件大小限制（< 1MB），服务端不做语音识别
- 需评估网络带宽和存储成本

### 2.3 明确不做

| 功能 | 原因 |
|------|------|
| 移动端 App | 无需求，用户确认不需要 |
| 公开注册/开放平台 | 固定小群，不需要 |
| 视频通话 | 需求弱，技术复杂度高，ROI 低 |
| 端到端加密 | 熟人小群场景，HTTPS + JWT 已足够 |
| 国际化/多语言 | 仅中文用户 |

## 三、非功能需求

### 3.1 安全性

| 编号 | 需求 | 优先级 | 说明 |
|------|------|--------|------|
| S1 | 服务端地址不暴露在仓库 | **高** | 将 ip 从代码中移除，改用域名或环境变量，防止 DDoS |
| S2 | 更新通道使用 HTTPS | **高** | 当前 HTTP，需申请 SSL 证书（Let's Encrypt 免费） |
| S3 | API 速率限制 | **中** | 防止暴力破解邀请码和恶意上传；登录 5次/分钟，上传 10次/分钟 |
| S4 | 文件上传魔术字校验 | **中** | 除 MIME 类型外，校验文件头 magic bytes，防止伪装文件 |
| S5 | JWT 加密存储 | **中** | 使用 Electron safeStorage 或 keychain 替代明文 JSON |
| S6 | 无 CSRF 保护 | **低** | Bearer token 认证已免疫简单 CSRF，暂不处理 |

### 3.2 可靠性

| 编号 | 需求 | 优先级 | 说明 |
|------|------|--------|------|
| R1 | 优雅关闭 | **中** | 注册 SIGTERM/SIGINT，释放 MySQL 连接池，完成在途事务 |
| R2 | 数据库迁移规范 | **中** | 从条件式 ALTER TABLE 改为版本化迁移系统 |
| R3 | 结构化日志 | **中** | 替换 console.log，支持日志级别和文件输出（推荐 pino） |
| R4 | 面板渲染崩溃恢复 | ✅ 已有 | render-session.js 防闪烁 + 超时兜底，保持现状 |

### 3.3 可维护性

| 编号 | 需求 | 优先级 | 说明 |
|------|------|--------|------|
| M1 | 拆分 App.tsx（1737行） | ✅ 已完成 | 已拆分为 6 个 Context + 三层组件，`App.tsx` 缩减至 73 行 |
| M2 | 拆分 main.js（1862行） | **高** | 拆分为 window-manager / ipc-handlers / updater / drag / tray 模块 |
| M3 | 消除硬编码 URL | **高** | 所有外部地址通过环境变量注入，不出现 IP 明文 |
| M4 | 后端测试覆盖 | **中** | 核心 Service（GomokuService、DailyQuestionService）单测 |
| M5 | 前端测试补充 | **中** | App 核心逻辑、ChatPanel、GomokuPanel 的组件测试 |
| M6 | E2E 测试 | **低** | 关键用户流程自动化验证，长期目标 |
| M7 | Node.js 版本约束 | **低** | 添加 .nvmrc / engines 字段 |
| M8 | Electron TypeScript 迁移 | **低** | 随拆分 main.js 时逐步进行 |

### 3.4 部署与运维

| 编号 | 需求 | 优先级 | 说明 |
|------|------|--------|------|
| D1 | 域名绑定 | **高** | 申请域名指向 `43.139.223.204`，代码中全部使用域名 |
| D2 | SSL 证书 | **高** | Let's Encrypt 免费证书，升级所有 HTTP 链接到 HTTPS |
| D3 | 代码签名 | **低** | macOS $99/年 + Windows $200-400/年，当前阶段不申请 |
| D4 | 应用容器化 | **低** | 当前单机裸部署可接受，未来考虑 Docker |
| D5 | CI 补充 Windows 构建 | **低** | 当前仅 GitHub Actions macOS 构建 |

## 四、数据需求

### 4.1 现有数据模型（保持不变）

当前 7 张表结构符合需求，迁移策略从条件式 DDL 改为版本化管理即可，不涉及表结构变更。

### 4.2 未来可能的模型扩展

| 功能 | 涉及表变更 | 时机 |
|------|-----------|------|
| 消息撤回 | `messages` 加 `deleted_at` 字段 | F8 实现时 |
| @提及 | `messages` 加 `mentions JSON` 字段 或新建 `message_mentions` 表 | F8 实现时 |
| 管理员 | `users` 加 `role ENUM('member','admin')` | F9 实现时 |
| 新游戏 | 新建对应游戏表（如 `draw_games`、`draw_moves`） | F10 实现时 |
| 自定义表情 | 新建 `custom_emojis` 表 | F11 实现时 |
| 日历/日程 | 新建 `calendar_events` 表 | F12 实现时 |
| 消息扩展 | `messages.metadata JSON`，兼容未来扩展字段 | 重构时预埋 |
